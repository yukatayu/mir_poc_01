02 / 得られた証拠

WRK-0046 が示したことと、示していないこと

実験の対象は、実際の save/load や branch model ではありません。一つの supplied finite linear experimental lineage の上で、opaque な AcceptedSuccess と disposable な Spent を置いた candidate-local な条件文です。記号や実験名を、Core state や public behavior として読まないことが重要です。

A0: 条件付き十分性

ordinary edge と一つの supplied restore edge の双方で Spent が保持され、consume が unspent source から spent target を作るなら、その有限 line に二つの counted consume は存在しません。

A1: omission/reset control

同じ bridge と ordinary-edge validity を残し、restore-edge preservation だけを外すと、post-restore の acceptance と Not Spent を含む exact two-consume trace を構成できます。

検証の強さ

sole Lean block は --trust=0 で通過し、53 retained declarations は axiom-free。閉じた A0 fixture と A1 control の双方を含みます。

正しい依拠上限

A1 は A0 の反証ではありません。また、preservation の唯一性・最小性・実装上の保存場所を導くものでもありません。

この証拠から言えること

  • 登録済みの有限 line では、restore-preservation を含む前提が two-consume を排除する。
  • その preservation を外した登録済み adverse fixture では、two-consume が可能である。
  • この限定された候補において、restore-preservation が load-bearing premise であることを示す。

この証拠から言ってはいけないこと

  • 全実行・全 admissible restore での global one-shot。
  • Spent が Canon の state、field、budget、SaveObject member であるという結論。
  • K0 の採択、receipt/identity/causality/actual persistence の設計、OBL/Gate/Phase の前進、実装認可。
過大解釈を防ぐ要点: supplied finite line を actual execution に、sufficiency を necessity に、opaque predicate を semantic inventory に読み替えることはできません。特に、WRK-0045 が凍結された branch-to-binding 問題を、新しい branch/key を追加して迂回修復してはいけません。

04A / T0 exit の条件

なぜ T0 のままなのか、どうすれば T0 を終えられるのか

T0 は「理論実験がまだ足りないから」だけで止まっているのではありません。T0 は、以後の全ての理論・実装が参照する語彙と統治上の基準器を、Canon の手続で固定する工程です。現在の v2 evaluation は壊れた JSON ではなく、固定された control と現在の blob が一致しないことを正しく検出した valid fail です。したがって、結果を無視して次へ進むこと自体が T0 の目的に反します。

1. 現在の直接原因

唯一の fresh v2 artifact は fixed source-hierarchy control と三つの fixed LAB notice control の drift を検出し、root result を fail としました。fail は pass の不足ではなく、現在の pin では acceptance route を開けないことを意味します。

2. なぜ自律作業で解消しないか

pin を維持するか、通常の Canon rebase proposal を始めるかは owner/Canon の統治判断です。agent が documentation や実験の都合で hash を差し替えたり retry を作れば、固定 control が守るべき再現性を失います。

3. WRK-0046 との関係

WRK-0046 は P017 周辺の parallel LAB evidence です。T0 profile の control、G0-D3、G0 exit を入力としても出力としても持たないため、成功しても T0 を終えられません。

4. 終了は一つの pass ではない

現在の one-off route は消費済みです。ordinary Canon amendment が後継 evaluation route を明示的に認可し、その route の valid pass、owner の exact-digest acceptance、Canon の exit record が揃うまで、official lifecycle は T0 のままです。

T0 exit の必要条件。矢印を飛ばしたり、LAB evidence で置換したりしない。
現在の valid failfixed control drift を正しく検出して停止している。ここを pass 扱いしない。
owner disposition現 pin を維持して defer するか、ordinary Canon rebase proposal と後継 evaluation route を認可するかを決める。
認可済みの後継 routerebase route なら、ordinary Canon amendment が新たな profile/evidence cut と evaluation route を明示する。消費済み v2 route は再利用しない。
exact evaluation認可済み後継 route を仕様通り実行し、artifact が valid で root result が pass であることを確認する。
G0-D3 acceptanceowner が exact artifact digest を明示的に受理する。pass 自体は受理を代替しない。

「いつまでも終わらない」状態を防ぐ運用

CP-1 の disposition を曖昧にしたまま、LAB の成功を積み上げて T0 exit の代わりにしないことです。defer を選ぶなら、T0 は意図的に停止している状態であり、失敗した実装作業ではありません。rebase を選ぶなら、その選択と後継 route を ordinary Canon process として記録し、固定 control の意味を検査可能に保ちます。

この repo が今すぐ実行できる準備

owner の判断を代行することはできませんが、current artifact、control drift の scoped audit、source hierarchy、exact evaluation 手順、acceptance packet の材料を整え、判断後に同じ手順を再現できるように保守できます。これは T0 を短絡せず、終えるための正しい準備です。
