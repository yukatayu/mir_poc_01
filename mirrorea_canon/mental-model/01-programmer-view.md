# 01 — プログラマの見え方(七箇条)

Mir で書くとき、あなたが持つべき心的モデルは次の七つだけである。

1. **読みは値、書きは出来事。** 変数を読むのは普通の式で、透過的に見える(裏では依存として記録される)。書くことだけが世界に痕跡を残す。
2. **状態には持ち主(locus)がいる。** `state` を宣言した場所がその持ち主。自分が持ち主なら代入はただの代入。
3. **持ち主でない状態への代入は「依頼を書いた」ことになる。** `World { player[target].hp = ... }` と普通に書けばよい。それは自動的に「World への依頼」に翻訳される。魔法ではないので、翻訳結果は devtools でいつでも見られる。
4. **`fails` は「起こることの列挙」ではなく「引き受ける失敗の宣言」。** ネットワークは切れ、権限は無く、相手は退出している — そういう世界で依頼を書くなら、その失敗を引き受けると書く。書き漏らせばコンパイルエラーで、何をどこに足せばよいかが返ってくる。
5. **名乗っても偉くならない。** role は自己紹介にすぎない。できることは admission でもらった grant が決める。key であること・場所にいること・接続していることも、権限にはならない。
6. **消えるかもしれないものを参照するなら、chain で「最悪どこまで劣化してよいか」を書く。** 劣化は前に進むだけで、勝手には戻らない。戻りたければ明示的に取り直す(取り直しは新しい出来事)。
7. **世界を後から変えたければ patch を書く。** patch は普通のソースであり、検査と受理を通ってはじめて世界に入る。断られても世界は汚れない。

考えなくてよいこと: シリアライズ形式、通信プロトコル、メッセージ順序の細部、observer への配信、監査行の生成。これらは全部、翻訳の産物として裏に生成され、しかし隠されずに可視である。
