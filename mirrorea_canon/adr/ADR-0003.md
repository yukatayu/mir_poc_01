# ADR-0003 — 並行書き込みモデル

**決定**: ある indexed state の同時点の書き込み権威は常にちょうど一つの owner locus にある。非 owner からの書きは request に elaborate され、owner が直列に裁く。権威の移動は明示的 handoff occurrence(witness 付き)による。

**理由**: 権威一元化は、failure row・capability・監査・save/load と最も素直に合成する。仮想空間の主要ワークロード(部屋・ワールドの権威サーバ)に一致する。

**却下した代替**:
- Verse 型トランザクション(投機+ロールバック): 表は綺麗だが、irreversible effect・witness・観測との整合が重く、失敗の説明可能性が下がる。
- Croquet/TeaTime 型複製決定論: 全複製に決定論を要求し、provider・外界効果と相性が悪い。
- CRDT 収束: 収束は保証するが「誰の意図が通ったか」の権限・監査意味論が弱い。

いずれも**拡張点として比較メモを theory/12 に保持**する(将来、特定 state 種別に対する opt-in は排除しない)。

**再考条件**: OPEN-003 — 高頻度共同編集(テキスト等)を S5 ライブラリとして載せる際、CRDT 的 state 種別を「owner が収束器である」と読める形で導入できるかを検討。core の単一権威原則自体は凍結。
