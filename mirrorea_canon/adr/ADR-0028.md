# ADR-0028 — SYS-2 ST/OW1 execution and bounded ordering refinement

Decision date: 2026-08-27

## Decision

Adopt PROPOSAL-031's two internal execution profiles for the selected SYS-1
kernel fragment. ST remains the deterministic single-thread reference. OW1
has one coordinator and one dedicated owner worker for exactly one combined
semantic owner/source-owner locus; a zero-capacity synchronous mailbox and
acknowledged commands are the selected implementation profile. The worker
exclusively owns the mutable M8 runtime. Admissions with any other combined-
locus count fail typed before owner state is duplicated or exposed.

Successful owner mutation linearizes at the actual acknowledged M8
`OwnerWrite` trace node. The paired owner read, per-key written version,
preceding writer/request, and M8 enqueue occurrence supply the selected
reads-from/coherence record. A failed or revoked serve supplies none of those
success facts. Designated remote input is read from worker-owned source-owner
state; its reply is derived from that acknowledged read and follows request →
serve/read → reply → receipt → evaluator consume. A mismatched caller-supplied
value fails before reply/receipt/mutation.

## Authority-generation visibility

The kernel keeps the M9 successor publisher from the same admitted seam.
Production revocation is performed inside M9 and fully retranslates the
authority inventory. A successor must keep the checked program identity,
advance the generation strictly, retain prior tombstones monotonically, and
preserve unrelated owner and designated-release lineages. ST refreshes M8
directly; OW1 waits for the owner worker's refresh acknowledgement. Kernel
publication occurs only afterward, and failed refresh leaves the prior
generation live.

A generation-0 request served after acknowledged generation-1 revocation is a
typed `MissingCapability` failure with no owner mutation. A write committed
before generation 1 remains committed, but a later reply/receipt transfers no
authority. New uses cannot be constructed from the revoked lineage.

## Bounded assurance

Adopt the finite SYS-2 transition model at bound 6 for the exact required-edge
families recorded by PROPOSAL-031. Missing-edge runs reach replayable typed bad
states. Full-edge ST and OW1 runs agree on the selected observable result.
Store buffering remains a separate weak-memory calibration and does not import
low-level memory order into Surface.

The accepted implementation/evidence cut is
`920d3fe050b8b909253f8511d9ad897272323ced`. OBL-058 records the finite model as
`model-checked-bounded`; OBL-059 records the selected ST/OW1 implementation as
`runtime-monitored`. Twenty-seven focused SYS-2 tests and preserved SYS-1/M10/
runtime regression, formatting, warnings-denied Clippy, diff checks, and four
independent review lanes accepted this bounded scope with no remaining
P0/P1/P2 finding. No Lean theorem or general proof is claimed.

## Lifecycle consequence

SYS-2 is completed and SYS-3 per-locus projection/artifact generation is the
active ADR-0026 milestone; SYS-4 is next. Theory remains T1. Broad PHASE-I1
exit and official I2 entry/exit remain unaccepted because the full
architecture/04 carrier freeze and OPEN-026/027 are not resolved and generated
per-locus artifacts/dispatch do not yet exist.

## Non-effects and reconsideration

This decision does not reinterpret `atomic_cut` as a fence, add
`memory_order_*` or mailbox/worker vocabulary to ordinary Surface, admit
multi-owner OW execution, claim a general scheduler/memory/data-race theorem,
define lock-free execution, generate or dispatch per-locus artifacts, freeze a
public API/ABI/wire, select real transport, or change lifecycle acceptance.

Reconsider only for a reproducible selected-fragment ordering violation,
stale authority mutation after acknowledged generation publication, ST/OW1
semantic mismatch, or a direct SYS-3/4 consumer that cannot use the internal
profile conservatively.
