# ADR-0013 -- T0/G0 governance profile と G0 substantive evidence

Decision date: 2026-07-15

**決定**: `phase-governance/t0-g0` version 1 を、T0 における
`plan/01-phases` の JSON 条件の解釈として採用する。正本の定義は
`plan/01-phases` であり、これは `arch/03-toolchain` の SCN-suite
`mir-conform` tool output でも、`spec/06-conformance` の C-static,
C-runtime, C-distributed 適合性でもない。

オーナーは、下記の repository evidence-cut における ADR-0001, ADR-0002,
ADR-0005, ADR-0009, ADR-0012 を G0 のために effective とし、同じ cut の
`root/glossary` baseline を prepared、`LAB:plan/153` の LAB-demotion evidence
をこの checkpoint の complete evidence として受理する。これは G0-D1 の exact
acceptance record である。G0-D4 は、追加の semantic / historical
LAB-demotion audit をこの checkpoint では waive する。将来の具体的 drift は
別 scope の audit を再開させうる。

唯一の production route は、一回限りの ephemeral evaluation で、
`LAB:plan/155` が記録する derived JSON artifact を一つだけ生成することとする。
producer implementation、generator、helper、schema、CI、Make target、new
evidence lane、又は report series を commit しない。この artifact は profile
definition、evaluation revision、owner record、accepted evidence cut、self digest
を bind する。

G0-D3 は **defer** する。従って profile result が `pass` でも、G0 exit,
T1 entry, ADR effectivity の追加、又は implementation state の変更は生じない。
exit には別の human acceptance がその artifact digest を参照し、canonical
exit record を残す必要がある。

## 理由

T0 は executable SCN phase ではないが、universal Phase-exit rule の JSON
condition を例外として消すべきでもない。狭い phase-governance profile は、
document/evidence review を semantic proof や implementation conformance と
誤記することなく、必要な structured evidence を残す。D3 を独立して defer
することで、evaluation result と Gate authority を混同しない。

## 帰結

- `plan/01-phases` が profile の field, checks, result, binding, non-effects を
  定義する。`spec/06-conformance` は SCN-only のままである。
- 既存五 ADR の status / maturity は、この G0-specific acceptance を表すために
  変更しない。
- profile の one-off JSON は LAB evidence であり、program meaning, authority,
  proof, SCN conformance, Gate exit の source ではない。
- exact profile format を変える場合は、通常の canon proposal / human decision /
  ADR / CHANGELOG procedure を再度通す。

## 却下した代替案

1. T0 を universal JSON rule の例外にする: lifecycle rule を曖昧にするため採用しない。
2. SCN conformance output を流用する: T0 の document/evidence review を実装適合性に
   偽装するため採用しない。
3. reusable producer を先に実装する: T1 exit までの moratorium と衝突するため採用しない。

## 再考条件

profile binding の具体的 drift、accepted evidence の具体的な不整合、又は G0 exit を
実際に適用する owner decision が発生した時に再考する。D3 defer 自体は、G0 exit を
承認する canonical record でのみ置き換えられる。

Let `B` be the commit that first records the single artifact recorded by
`LAB:plan/155`. The evaluated revision must be `B`'s immediate first parent
`C`: `C` descends from the accepted repository evidence cut, contains the
complete ADR-0013/profile-v1/INDEX adoption patch, has a first parent lacking
at least one exact ADR-0013 or profile-v1 blob in `C`, and lacks the artifact
from its own tree. No other revision is valid.
