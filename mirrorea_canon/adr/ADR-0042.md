# ADR-0042 — Finite source-declared read-only provider effect

Decision date: 2026-09-08

## Decision and authority

ADR-0034のowner-delegated bounded authorityにより、PROPOSAL-045のcandidate Aと
spec/17を選択する。integration baselineは
`55f1fd7f76b86a2fc6a846c0133d55d5c8213831`。parentが独立したCanon-first planner
reviewとcontract reviewの指摘を統合し、修正版のP0/P1/P2なしを確認して行う限定決定
である。新しいowner message、実装完了又はmilestone受理を主張しない。

ordinary sourceに宣言されたzero-argument read-only external effectを、既存の
遠隔locusで実行する。source/Core/resource/consumer/failure/allowanceをchecked
artifactとgenerated communicationへ保存し、private QUICのframing/sessionは
共有するが、effect request/result、use authorityとconsumeをOwnerRMW/FabricReceipt
から分離する。追加provider process、service registry又は新transportは要求しない。

T0 trusted adapterから専用の非機密T4 host fixtureを実際に読み、typed Int又は
宣言済みfailureを返す。missing resource、operational adapter failure、invalid result、
policy denial、resource exhaustionを区別する。provider/transportは権限を発行しない。
独立したeffect permission、current generation/incarnation、use-time revalidation、
bounded supervisor/resource envelope、CallStartedの直列化とretained decisionを要求する。
応答消失はpending/remote-unknownであり、nonexecution、terminal failure、blind retry
又はexactly-onceへ変換しない。consumerへの値releaseとobserver metadataを別に検査する。

candidate Bの専用effect service/transport-facing familyは、Aの意味区別を共有表現で
保存できない具体的反例が出た場合の代替であり、並行実装しない。必要な内部enum又は
generated edgeの追加を避けることは目的ではない。

## Scope and acceptance requirements

Direct consumerはI3-3のprovider failure familyとeffect orderingである。spec/17の
source/check/snapshot/grant/static falsifier、実process/QUICでの異なる実I/O値と
provider failure、duplicate/loss/revocation/retention/observationの検証及び独立reviewを
実装受理の条件とする。source-only対応を実provider実行と呼ばない。LAB Plan 250が唯一の
roadmap、Report 2606が唯一のI3-3 reportであり、追加milestoneを作らない。

既存source、owner意味、M5/M6/M7 Lean evidenceの範囲、Theory T1、broad I1 residual、
official I3 lifecycleは変えない。T0/T4 fixtureはT2 sandbox又は一般Browser/Host安全性
の実装ではない。public grammar/API/ABI/wire、arbitrary FFI、provider registry、I4/I5、
domain primitive、general security/liveness/proofを選択しない。

I3-3のみactiveである。全20 familiesとorderingを検証・独立受理し、commit/pushと
remote parityまで完了したらowner指示どおり停止する。I3-4は明示resumeまでinactive、
Plan 250は保持し、pauseをblocked又はprogram closeと混同しない。
