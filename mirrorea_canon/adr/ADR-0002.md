# ADR-0002 — Event の三分類

**決定**: 「イベント」を次の三つに分け、以後この語だけを使う。

1. **occurrence**(S2)— 実行履歴 DAG のノード。write・send/receive・grant/use・cut 等。理論と devtools の対象。ソースコードに出現しない。
2. **request / publication**(S1)— elaboration が生成する owner 宛依頼・可視化辺。ソースに出現しないが、Core IR と devtools では**必ず可視**(隠さない)。
3. **domain event**(S5)— `when attack(target)` のようなハンドラ語彙。ソースに出現してよい(するべき)。

**理由**: 「Event をソースに極力出さない」という軸は (1)(2) を S0 から隠す話であり、(3) は別物。混同すると「イベント駆動なのにイベントが書けない」という偽の矛盾が生じる。

**帰結**: 普通の親への代入は、(3) を書かずとも (2) に翻訳され (1) として履歴に残る。「代入はイベントを飛ばす」は「cross-locus write は owner-directed request occurrence に elaborate される」と読み替える(theory/03)。

**再考条件**: OPEN-002 — (2) のうち publication と request を別語に分けるべき圧力が S4 で生じた場合、名称のみ再考(分類自体は凍結)。
