# ADR-0036 — Browser/Host and provider trust boundaries

Decision date: 2026-09-01

## Decision

Adopt PROPOSAL-039, `arch/07-browser-host-trust-boundaries` and
`arch/08-browser-host-security-invariants`. Preserve BND-007
as Runtime/Projection to View and add BND-010--016. Admission, verification,
package/publisher identity, process, route, transport, session, certificate,
provider, renderer, device and host facts are never Mir authority; participation
requires a separate explicit owner/grant/witness decision.

View/provider owns no authoritative domain semantics or direct mutation path.
It may perform presentation-local computation over an already observer-safe
projection. Input returns only as a typed command/effect request that the Mir
semantic owner revalidates. T1 checked untrusted packages have no raw FFI. T3
privileged native integration is separate, least-privilege, provenance-bound,
revocable and preferably process-isolated. Resource enforcement and observation
limits fail closed. Crossings bind exact content/request, instance/incarnation,
target, policy/grant epoch, authority lineage, frontier/freshness and resource/
observer scope as applicable. Use-time revalidation, queued/in-flight revocation,
metadata redaction and ambiguous external-effect state are explicit; ambient
component authority cannot fill a missing binding.

## Trust and implementation consequence

Trust-tier T0--T4 labels are local to `arch/07`; they are not theory T0--T2,
semantic strata, project/product layers or an automatic privilege order. T0
enforces Mir policy but does not mint authority from its own identity. T4 is the
host substrate, not the Browser admission kernel. T2 remains typed/sandboxed;
ambient native access belongs to separately admitted T3.

I3 transport and runtime must preserve these boundaries and observer/redaction
limits but do not implement I5 package, sandbox, View or plugin mechanisms.
I3-0 is the sole active goal after this decision; both reliable-stream candidates
remain UNSELECTED, OPEN-032 remains unresolved, and official I3 lifecycle remains
unentered.

## Rejected alternative

Do not keep all Browser/View/FFI concerns inside BND-007. That alternative hides
the authority boundary between admission and grant, the direction change between
projection and input, and the different safety claim of typed providers versus
privileged raw native integration.

## Reconsideration and non-effects

Reconsider if a future direct consumer cannot implement fail-closed admission,
resource enforcement, revocation or redaction without weakening the North Star;
if ordinary packages require raw native access; or if package admission cannot be
separated from semantic grant. Such a finding triggers owner review rather than a
silent weakening.

This decision freezes no package/origin/signature/storage format, browser UI,
sandbox technology, renderer/engine, Unity/Unreal plugin ABI, FFI/API/ABI/wire,
provider protocol, deployment or production claim. It changes no accepted I2
runtime behavior, Theory T1, broad PHASE-I1, proof/model/OBL, SCN or sample.
