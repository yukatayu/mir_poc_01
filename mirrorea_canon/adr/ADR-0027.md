# ADR-0027 — SYS-1 semantic runtime kernel and internal carrier

Decision date: 2026-08-26

## Decision

Adopt PROPOSAL-030's bounded SYS-1 contract. A crate-private
`SemanticRuntimeKernel` is the production semantic state/occurrence path for
ordinary `run_source` and generic checked `OwnerEvent`. It consumes the exact
checked Core and a sealed M9 execution seam, owns and serves through the
admitted M8 runtime, and permits the M8 runtime to be extracted afterward.
The M10 profile, conformance evidence generator/verifier, release identity,
and CLI facade depend on or surround this path; none is an input to the
kernel.

The specialized historical M10 SCN-04, SCN-09, SCN-10, and route-patch
runners remain preserved regression-only paths. This ADR does not claim that
every legacy M10 scenario runner is routed through the kernel.

## Internal carrier boundary

Accept these two non-public lifecycles:

```text
owner request:
  request -> serve -> reply -> receive/receipt

designated remote input:
  request -> source-owner serve -> reply -> receive/receipt
          -> designated-evaluator consume
```

The kernel issues request identity and ordered occurrence identity; queue
position is scheduler state and is not request identity. Each carrier retains
the exact checked operation/dependency, source/Core provenance, origin
principal/locus, owner or producer/evaluator loci, typed success or declared
failure, effect/failure rows, visibility/redaction, membership epoch and
incarnation, capability/witness references, and any applicable input
frontier, producer release tuple, receipt identity, and consumption state.

The designated remote-input lifecycle is a bounded typed-effect request and
result boundary, not a generic provider registry. Producer release authority
and evaluator decision authority remain distinct. A receipt communicates a
result and causal occurrences only: it transfers no authority or ownership
and cannot by itself authorize mutation.

## Fail-closed rules

All provenance, target, origin, authority, freshness, and identity validation
precedes semantic occurrence creation and M8 enqueue. Source-free or forged
carriers cannot mint Core, state, membership, capability, witness, or
authority. Invalid/duplicate/stale/wrong target or source, restricted
visibility, producer/evaluator authority substitution, FIFO mismatch, and
malformed factory inputs return typed diagnostics or declared failures
without unintended mutation. Duplicate rejection is not a hidden retry or an
exactly-once guarantee.

## Acceptance record

The accepted implementation/evidence cut is
`94e3707c7bc98d4a0764c51f13a12b1dae1968c6`. The crate-private kernel is used
by ordinary source execution and generic checked owner schedules, consumes
the M9 sealed seam, owns/extracts the M8 runtime, and has no dependency on M10
profile/verifier/release/CLI types. Thirteen focused runtime tests cover the
positive lifecycles and representative falsifiers; the changed runtime crate,
M10 source/CLI/conformance regressions, full workspace, formatting, and
warnings-denied Clippy passed. Independent semantics and code-quality reviews
accepted the cut.

This evidence is classified only as `runtime-monitored`. No Lean or bounded
model-check evidence was changed, and no general theorem is claimed. Legacy
M8 public receipt builders are retained fixture APIs rather than this I2
carrier.

## OPEN-030 and lifecycle consequence

OPEN-030 is closed only as this narrow I2-internal bounded contract.
Architecture/04 remains L2-working, and broad PHASE-I1 remains unaccepted
because OPEN-026, OPEN-027, and the full internal carrier freeze remain.
Theory lifecycle remains T1; no broad PHASE-I1 or official I2 lifecycle state
changes in this decision.

The kernel admission is an immutable M9 snapshot. Visibility of revocation
after enqueue or serve is therefore an exact SYS-2 residual. SYS-2 must map
revocation and publication visibility to its ST/OW ordering contract before a
threaded claim can close. A stale use past that required edge is the reopen
trigger.

## Non-effects

This decision does not freeze public API/ABI/wire or JSON field names, define
real transport or retry/exactly-once behavior, introduce a generic handler
registry, import memory-order vocabulary into Surface, alter specialized M10
runners, change proof status, accept broad PHASE-I1/I2 lifecycle, or change
the official theory lifecycle from T1.
