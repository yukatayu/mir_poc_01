# ADR-0023 — M8 deterministic runtime admission

## Decision

Adopt theory/17 and spec/09 as the M8 finite deterministic-reference runtime
boundary.  M8 takes an immutable M7 checked artifact and explicit runtime
admission evidence.  A request name may deterministically select only a
checked plan retained by that artifact; M8 does not accept source, an AST, a
classifier result, fixture-name lookup, report output, or an externally
supplied/reconstructed evaluator side table as an alternate semantic carrier.

An accepted M8 runtime input binds one checked-program identity to its static
environment, checked evaluation/Core shape, effect/obligation shape, stable
source-to-Core map, residual source references, and the M8 evidence rows.
Any mismatch rejects before runtime semantic state changes.  M8 runtime
admission is distinct from M7 static `execution_is_admissible`; M8 never
rewrites an M7 artifact or turns its residuals into empty M7 residuals.

M8 may settle only the selected finite visibility, relation-lifetime,
fallback-validity, and value-visibility/redaction evidence.  `AuthDeferred`
and `VerifyDeferred` remain `DeferredToM9`: no authority/capability success,
proof verdict, effect, semantic mutation, or runtime admission follows from
either one.

The M8 finite state is one fresh configuration with M5-aligned state
categories: admitted program/admission data, occurrence/dependency history,
owner queues/state,
membership/capability/witness/lease records, relation and designated stores,
local cut/save provenance, and bounded patch lifecycle rows.  This is one
semantic carrier, not a claim that the fresh Lean, M5, M7, or Rust structs are
identical types.  Presentation-only context remains outside this state.

## Consequences

- Deterministic lowering is source-map ordered and uses checked typed actions.
- Owner service is FIFO at the owner and validates capability/witness context
  before its RMW; failure is fail-closed for the store.
- Relation remains owner-held; consumer projection is local/read-side.
- Designated data retains nominal input/result frontiers, version, evaluation
  policy, observation policy, and policy stamp.
- Local save/restore includes all M8 semantic state; rejected/deferred patch
  rows add lifecycle evidence without semantic mutation; observer-safe output
  is a typed projection rather than a raw debug trace.

## Non-effects

This decision does not prove general scheduler determinism, general cut/load
or patch theorems, observer noninterference, M9 authorization/verification,
transport/receipt delivery, distributed execution, official C-static or
C-runtime SCN conformance, final grammar, or a public contract.

## Reconsideration

Reconsider if a selected M8 action cannot be derived from the retained M7
artifact without source reconstruction, if a required finite residual needs
M9 authority/proof semantics, if one semantic state cannot save its queue /
identity / policy / patch data, or if a negative path changes semantic state.
