# ADR-0021 — M6 bounded ordinary Surface

## Decision

Adopt `spec/01-lexical-and-modules`, `spec/02-surface-grammar`,
`spec/03-static-semantics`, and the M6 delta of `spec/04-core-ir` as the
bounded M6 source-facing reference.  This replaces ADR-0008's retained
pre-M6 profile as the current grammar direction; ADR-0008 remains historical
compatibility evidence.

The accepted syntax is intentionally ordinary and bounded: modules, loci,
principals, type declarations, indexed state field blocks, literal-self actor
handlers, same-owner action blocks, maintained relation declaration blocks,
designated result evaluation, and explicit non-executable deferred
auth/finite-refinement forms. It has no
Surface syntax for send/receive, occurrence/envelope/witness machinery,
receipt/release, presentation contexts, transport, or runtime control.

An owner action separates authority origin from evaluation site.  A same-owner
action has `Role[self]` authority origin and the explicit owner locus as its
evaluation site; it lowers through the M6 template to M5's owner-RMW fragment
with request/write edges, a separate source-to-Core local-dependency entry,
and capability/witness obligations, but without a receipt fact. Cross-owner dependencies are diagnosed as requiring
an explicit receipt path, not recovered by a hidden request, snapshot, or
authority grant.

`Role[self]` is parser-enforced, not a binder convention: a different bracket
actor is `RoleActorMustBeLiteralSelf`. Before owner-RMW construction, the
classifier rejects a fieldless write target as `FieldlessAssignmentTarget` and
a target state outside the action locus as
`CrossOwnerWriteTargetOutsideActionLocus`; both are distinct from the RHS
`CrossOwnerOperandRequiresReceipt` boundary and produce no CoreTemplate.

The template keeps nominally separate result-frontier and binding-frontier
fields. Designated evaluation carries only a result frontier/version and
`publish-value`; maintained relation carries only a binding frontier,
`publish-relation`, and optional consumer-local projection. `publish value`
and relation mutation are typed diagnostics. Source spans are retained in
parsed forms, CoreTemplate fields, source-to-Core entries, generated
edges/obligations, and diagnostics. Auth and finite refinement forms are
successful non-executable typed deferred templates only.

## Consequences

- M7 consumes one finite M6 grammar/classification input under ADR-0022;
  this does not turn the M6 decision into a general checker/runtime claim.
- `=` is not relation syntax: owner action mutation and designated result
  binding are one-shot templates; a maintained relation uses `relation`.
- M5 remains unchanged.  The M6 Lean classifier is a separate finite source
  classifier, not an import, adapter, or new M5 theorem.
- OBL-048 records only the exact trusted finite classifier/span evidence.

## Non-effects

This decision does not freeze a final public grammar, concrete parser AST,
diagnostic IDs/repairs, Core exchange JSON, API/ABI/wire, runtime, transport,
SCN conformance, M7 completion, M8 execution, M9 authority/verification
semantics, general elaboration theorem, or deployment.  It does not introduce
`PresentationContext` as source semantic state or weaken any authority,
receipt, label, fallback, or no-hidden-communication invariant.

## Reconsideration

Reconsider if the finite classifier finds an accepted source form requiring a
hidden default or a result/relation-frontier conflation, if a source span
cannot be preserved, or if the M7 direct consumer needs a construct outside
this grammar that cannot be an explicit later extension.
