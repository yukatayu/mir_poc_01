# 10 — I3-2 multi-process runtime mapping

Direct consumer: I3-3 network failure, retry and ordering refinement after
explicit resume.

Blocker reduced: I3-1 transported generated bytes over a real stream but did
not yet place accepted images in independent operating-system processes and
execute an owner-local mutation remotely.

Acceptance use: I3-3 gets one real, source-derived process/transport seam at
which faults can be injected without inventing semantic routes or authority.

ADR-0039 accepts this finite Linux x86_64 localhost mapping:

```text
ordinary source
  -> one supervisor build/check/admission
  -> exact per-locus image + retained one-shot start binding
  -> process-a {ParticipantA, ViewerC}
  -> private QUIC reliable bidi request
  -> process-b {WorldAuthority, ParticipantB}
  -> owner-local serve/write
  -> generated QUIC reply
  -> requester-local receipt
```

The image descriptor is tainted input. A distinct inherited control descriptor
contains the retained start/peer commitments; both must agree before runtime
start. The selected adapter owns a live mTLS QUIC connection and its stream,
requires exact peer leaf SPKI and a reciprocal run/image/program/projection/
cohort preface, and then invokes crate-private decoded admission. This gate
establishes delivery origin/integrity only. Sealed receiver M9, owner and pending-
request checks remain the semantic authority gate.

The supervisor joins four actual child delivery records to the generated
contracts. Each record carries observer-safe source/Core/source-artifact/
target-artifact/edge/carrier/semantic-request/network occurrence references.
Owner serve/write and requester receipt references complete the runtime chain.
Counts are derived from these record sets; they are not inferred from nonempty
source text, image buffers or expected values. Children own distinct store
identities and no store handle crosses the process boundary.

Clean success requires both distinct `exec` PIDs to exit zero naturally and be
reaped without force kill. One post-preflight absolute lifecycle deadline covers
child execution, natural-exit observation and reserved force-reap observation.
Late zero-exit observation, nonzero exit, hang, setup failure and undersized
reaper allowance are typed failures. Cleanup can force-kill and reap a child but
cannot convert that outcome into success.

The mapping is private/provisional and `runtime-monitored`. It is not the I3-3
failure/ordering contract, a public process/wire/certificate/API ABI, a package
or Browser/Host boundary, production support, durability, exactly-once or a
general proof. Synchronous preflight and exact return time under host suspension
are outside its child-lifecycle bound.
