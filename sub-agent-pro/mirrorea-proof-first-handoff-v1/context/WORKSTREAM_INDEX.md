# 作業と要件の索引

`workstreams.json` はW0の現場照合とF0.3のW1～W8を接続する候補地図。公式I/T phaseではない。W8は今回の完了必須ではない遠期である。

`requirement_work_map.json` は要件表の119 IDをすべて維持し、F0.3の次consumer・命題・SC・Qへ対応づける。元の`approved=false`や`requirement_completed=false`を上書きしていない。

原本の詳細は `materials/mirrorea_system_map_v1/requirements.json` と `materials/mir_foundation_F0_3/REQUIREMENT_TRACE.json` を読む。この索引は新しい意味や受理を生成しない。

とくに、型/証明の局所理論（TY/CT/VF）、認証/認可（AU）、観測（OB）、進化（EV）、保存（SV）の接続を別々の完成にせず、SC-24と二実行の検査で同じidentityへ接続する。SC-24の新しい設計を、実行済みSC-24と呼ばない。
