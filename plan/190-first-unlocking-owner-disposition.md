# Plan 190 - First unlocking owner-disposition reading and re-triage

## Role and authority

This is LAB repository memory for the current owner-decision sequence. The
owner disposition itself is recorded in `PROPOSAL-009`; this plan records its
LAB re-triage consequence. It does not open a `WRK-####` record, select a
proof interface beyond that recorded choice, change an OBL, move a Gate or
Phase, or claim a theorem.

## Question

After Plans 184 and 189 found no standing-eligible autonomous theory package,
what is the smallest owner disposition that can permit a fresh, bounded
re-triage without selecting more semantics than necessary, and what follows
after it is recorded?

## Recorded disposition

The owner recorded `PROPOSAL-009` option A as accepted on 2026-07-24 through
the proposal's Canon decision surface. A later OBL-001 proof-facing design
package may therefore state THM-001's existing every-write clause directly over
elaborated Core `c`.

This removes only the direct-Core-versus-output/Core-bridge decision stop line.
It does not choose a `Result` carrier, correspondence, enumeration or duplicate
policy, Core representation, traversal, occurrence relation, equality, Lean
API, outcome totality, or runtime occurrence model. It is not an OBL, proof,
Gate, or Phase change.

## Why PROPOSAL-003 is not prior

`PROPOSAL-003` organizes later OBL-020 formalization packages. It deliberately
does not select a transition, `Step`, `WellFormed`, frame, membership relation,
or proof decomposition. The existing OBL-020 stop line therefore remains after
any P003 answer. Its answer is not a prerequisite for a narrow static
Core-write re-triage under P009 A.

## Post-disposition re-triage

The Plan 184 screen was rerun against the post-disposition tree. No new L3
record is selected. The direct-Core route now passes its owner-boundary reopen
condition, but the remaining standing-eligibility conditions are not met:

1. the existing LAB OBL-001 source is an opaque `Result` / `GeneratedWrite`
   statement draft; it provides no pinned, admitted direct-Core write object or
   literal mapping to test;
2. repeating the Result/write coverage gap would duplicate WRK-0007 and
   Plan 180;
3. no current binary retain/reject consumer names a direct-Core classification
   as its input; and
4. defining an occurrence traversal for `write`, request-carried `op = write`,
   `seq`, or `cond` would select the representation/traversal/occurrence
   boundary that option A deliberately leaves open.

An accepted P009 A never creates a research package by itself. A future
steward must rerun the Plan 184 screen against the then-current tree and find
all of:

1. an existing admitted LAB lane and exact pinned source locus;
2. a non-duplicate question with a concrete alternative or falsifier;
3. a current binary retain/reject consumer;
4. a result class, permitted evidence path, non-effects, and rollback that
   satisfy ADR-0014; and
5. an adverse branch that does not select another reserved relation, including
   outcome totality, value flow, occurrence identity, or runtime behavior.

Absent all of those conditions, the correct post-decision result remains no L3
package. Reopen only when an exact, pinned, already-admitted LAB object exposes
a noncanonical direct-Core write classification or literal mapping and a named
current importer/package supplies explicit binary retain/reject actions.

## Dependency limits

P009 A is not a prerequisite for unrelated ADR-0014-eligible research. It is
not sufficient for a shared T1 model, OBL-020 work, outcome totality,
read-value flow, successful receipt, service/admission identity, grammar
closure, cost-bound substitutability, Gate action, or T1 entry. P008 becomes
relevant only if a future narrow package relies on outcome totality or crosses
into OBL-021.
