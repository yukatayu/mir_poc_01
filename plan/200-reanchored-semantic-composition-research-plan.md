## 自走する順序

### R0 - Common-cut re-anchor

1. current Canon cut を pin し、C0--C7 が利用する literal fact を source/section/digest/
   authority-class/non-claim として manifest 化する。
2. historical WRK の evidence cut と current fact を混同しない。
3. proposal detail、scenario notation、current grammar/Core を区別する。

R0 の falsifier は、同一 fact が source cut によって変わる、又は authority class が
literal source だけでは決まらない場合である。その場合は downstream 結論を止める。

### C0 - Four separate front-end questions

| Package | Disposition | Narrow question | Stop / reopen condition |
| --- | --- | --- | --- |
| C0-A source authority | `complete-by-R0` at the pinned R0 cut | current lexical/grammar/static source と selected-direction detail を source-local にどう分類するか | R0 が pre-enumerated span を literal に分類済み。Canon cut、source span、又は authority wording が変わるか、source 間の precedence/reconciliation が必要なら別 record で reopen する |
| C0-B domain staging | retained conditional lemma | lexical、parse、static、`WellScoped` elaboration の domain を非循環に分けられるか | `WellScoped` を elaboration success で定義する、又は candidate edge を current Canon rule とする |

P008 A は totality を determinism から分離する direction であり、exact domain 又は
diagnostic-code completeness を既に決めたものではない。C0 は P004 candidate の

R0 の `complete-by-R0` は provenance の完了であり、C0 の semantic domain、accepted/

### C2 - Five separate identity questions

| Package | Narrow question | Stop condition |
| --- | --- | --- |
| C2-A anti-collapse vocabulary | **closed as WRK-0030:** source-owned termsを WRK-local question label として index し、label 間の documentary non-substitution だけを retained | field partition、equality/identity、binding relation、attempt cardinality、replay classification はなお未選択 |
| C2-B identity anchor | request occurrence reference と explicit issuance token を candidate として比較できるか | Core primitive、edge schema、hidden side relation、wire commitment が必要になる |
| C2-C admitted-execution binding | non-authoritative claims と authoritative membership/verdict/grant/witness/history をどう関連付ける必要があるか | locus/transport/token possession を authority にする |
| C2-D replay policy | in-flight/success/reject/stale/restore の同一 semantic request attempt を total に分類できるか | exact failure family、retry/acknowledgement、unbounded hidden history を選ぶ |

「nominal issuance identity」は Oracle の advisory candidate であり、現行 Canon の
constructor ではない。C2-A の six headings は `PAYLOAD_QUESTION`、
`VALIDATION_CLAIMS_QUESTION`、`BINDING_QUESTION`、`REQUEST_UNIT_QUESTION`、
`ATTEMPT_UNIT_QUESTION`、`REPLAY_CLASSIFICATION_QUESTION` という WRK-local question
label であり、Canon object/carrier/predicate ではない。source fact 又は comparison を一つの
label に記録しても、別 label の答えにはならない。この documentary non-substitution を越えて、
payload equality、transport/queue/session identity、request identity、attempt cardinality、
replay policy、save/load classification を選ぶ必要が出た時点で owner/Canon proposal 又は
C2-B--E の successor に切り替える。

### C1/C6 - Independent candidate families

C1 は snapshot/evaluation locus/read-modify-write fusion を選ばず、各 candidate が
WRK-0024 lost-update trace をどう admit/reject/prevent するかだけを測る。C6 は
`scalar-cell` と `terminal-target` を別 package にする。前者は distinct scalar Core
declaration と already-declared finite-domain elaboration を比較し、後者は immutable
declared value/terminal declaration 等の explicit target form を比較する。いずれも
hidden membership key、type default、unbound terminal、hidden reacquire を禁止する。

### C3/C5/C4 - Value flow and occurrence facets

1. C3 は V1/R1 に従い、typed pending control、one receipt to one resumption、failure
   suppression、linear `Delta` を candidate-local に検査する。
2. C5 は conditional A2 を先に検査する。verdict-time membership/grant/witness issuance
   が一体であり、named facet で既存 causal edges を構成でき、rejection residue が無い
   場合だけ A2 family を継続する。別 failure/observable/schedule が出れば A1 successor
   を要求する。
3. C4a は SW1 の service/mutation/validation facet を一 occurrence に載せる local
   model。C4b は C2 binding/replay、C5 facet、C3 value flow と統合する。validation と
   mutation の間に schedulable phase が必要なら SW1 を修理せず decomposed successor を
   要求する。

### C7 - Ergonomic inference

C7 は全候補の explicit semantics が揃ってからだけ実施する。省略は、(a) normative
input から一意、(b) elaborated artifact が fact と根拠を復元、(c) owner の explicitness
mandate に反しない、の全てを満たす場合のみ候補になる。final store の一致だけでは不足で、
value/receipt/pending/occurrence/authority/failure/history/save-load の観測が一致しなければ
reject する。

scalar/default、semantic request/pending/grant/witness identity、read materialization、
snapshot/evaluation choice、dynamic authorization verdict は source inference にできない。
fresh identity は source omission の推論ではなく、明示的に生成・保持すべき semantic fact
である。

## Shared-model proposal gate

次の全てが evidence-backed になるまで shared proof-facing model を proposal しない。

1. C0 の non-circular domain と outcome/coherence/diagnostic distinction。
2. C2 の equality/identity/binding/replay/persistence distinction。
3. C1/C3 の read basis、receipt、pending linearity、failure suppression。
4. C5/C4 の A2/SW1 facet と causal relation、failure-no-mutation。
5. C6 scalar-cell/terminal-target の declared correspondence と history behavior。
6. C7 full-observation equivalence。
7. DAG、authority lineage、cut/save-load、no-hidden-communication と各 candidate の
   traceability。

複数 candidate が残る場合は comparison ranking と successor proposal を作るだけで選ばない。
一候補だけが残っても、Canon amendment、OBL、implementation authorization を意味しない。
