# Plan 231: K0 R/L Factorization Preflight

## Role and authority

This is LAB design preparation for the open K0 card in Plan 230. Canon remains
normative. The artifact compares only the presentation granularity of the X1
relation-state family: semantic residence and the subject of abstract restore
correspondence. It selects no Canon schema, relation arity, field layout, key,
identity, transition, occurrence, causal generator, failure row, Config or
SaveObject placement, restore function, serialization, source form, runtime,
proof, or public behavior.

P017 already selects an explicit relation-valued exchange component for one
V1/R1 cross-locus read. Plan 230 selects neither K0 nor a relation presentation;
it directs R/L review before B/T/U/C. WRK-0044 supplies only static
explicit-premise distinction evidence and cannot establish dynamic or restore
properties.

## Scope and common K0 R/L constraint ledger

The following are common Canon constraints and review headings, not a shared
candidate schema.

| Constraint | Required reading |
| --- | --- |
| semantic anchor | q is an existing request occurrence within one current or admissibly restored history; it is not source syntax, public token, transport/session key, or global cross-load identity |
| residence | the X1 exchange component has a named semantic relation residence, not evaluator state, a proof relation, a queue convention, source/payload/span coincidence, or transport metadata |
| dynamic domain | every in-scope q has exactly one requester-side pending administrative binding; equal incidental facts cannot merge effective pending, result, receipt, or use state |
| K0 rejection | a raw rejected delivery candidate is outside the semantic exchange transition system and leaves receipt-pending, owner-result availability, and accepted-use budget unchanged; it creates no rejection state, occurrence, requester failure, or restore frontier |
| observation | no observer projection, export, debug view, or storage-to-observation inference is claimed |
| restore | every live fact used after load needs causal-or-channel closure and abstract correspondence without pre/post equality, global identity, function, or selected storage representation |
| evidence cap | no reachability, transition, one-shot, no-merge, no-duplicate, no-reset, validation, causal, or runtime property follows from WRK-0044 static evidence |

For any candidate fact, the card records exactly one classification: C for pinned
Canon, H_K for candidate-local hypothesis, D_K for erasable definition over C
plus H_K, OPEN, Canon gap, or out of scope. An unclassified item is a hidden
choice.

external rejection is not an additional frontier.

## Delta A-Sigma: integrated relation fiber

### A-Sigma candidate-local classification

| Class | A-Sigma content |
| --- | --- |
| H_A-Sigma-R | One candidate-local relation family is the semantic residence. For each in-scope q, its q-scoped fiber is primitive but not a first-class exchange object, key, public identity, or cross-load identity. |
| D_A-Sigma-R | Candidate-local non-exhaustive predicates expose the fact classes required for review. They are not fields, constructors, or a complete lifecycle classifier. |
| H_A-Sigma-L | One abstract correspondence ranges over whole pre-load and restored q-scoped relation slices. It uses neither fiber equality nor a restore function. |
| OPEN_A-Sigma | relation arity/carrier; exact predicates; primitive versus uniquely derived facts; exact correspondence formula/properties; all B/T/U/C content; dynamic evidence. |

### A-Sigma review questions

1. Can every required fact class be reviewed without turning the fiber into an
   independently addressable exchange object?
2. Can exactly one pending binding per q be stated without saying exactly one
   envelope object per q?
3. Can a whole-slice correspondence expose closure for each relied-on fact, or
   can it hide loss, duplication, recombination, or reset?
4. Does a proposed fact projection amount to a fixed record field or complete
   tagged lifecycle?
5. Does any use of the fiber implicitly compare it across requests or loads?

A-Sigma stops if it needs fiber identity, fiber equality, unique envelope identity,
fixed fields, option slots for every frontier, a tagged union, restore
functionality, or a selected persistence representation.

## Delta B-Pi: factorized relation family

### B-Pi candidate-local classification

| Class | B-Pi content |
| --- | --- |
| H_B-Pi-R | Two or more candidate-local q-anchored relation families are independently primitive semantic residences. There is no common exchange witness, record, latent identifier, or shared saved key. |
| H_B-Pi-RL | An explicit candidate-local coherence condition constrains joint interpretation. It states only static compatibility and non-sharing; it does not encode transition, reachability, or exhaustive lifecycle. |
| H_B-Pi-L | One joint coherence-preserving correspondence relates the factorized families across load. Independently matched family components cannot be recombined into one restored exchange account. |
| OPEN_B-Pi | number/signatures of relation families; coherence formula; primitive placement; joint correspondence properties; all B/T/U/C content; dynamic evidence. |

### B-Pi review questions

1. Are all factorized families semantic residence rather than proof/evaluator
   associations?
2. Does the coherence condition avoid an existential common record, token,
   branch witness, or hidden q key?
3. Does it state only compatibility rather than exactly-one frontier,
   successor, reachability, or transition order?
4. Can exactly one pending binding and effective-state non-sharing be reviewed
   without an additional identity?
5. Does the joint correspondence prevent restored splice of pending facts from
   one pre-load branch with outcome/use facts from another?

B-Pi stops if its family index is a reusable field inventory, coherence is
implemented by a latent common witness, individual per-family correspondences
can splice components, or it needs a key, equality, restore function, or
storage form.

## Structural comparison and collapse rule

A-Sigma and B-Pi are not two full relation models. Their only possible semantic delta
is primitive placement:

| Presentation | Primitive candidate commitment | Derived or candidate-local material |
| --- | --- | --- |
| A-Sigma | one whole q-scoped relation fiber | non-exhaustive fact predicates over that fiber |
| B-Pi | two or more q-anchored relation families | explicit coherence and joint no-splice obligation |

Their restore delta follows the same distinction:

| Presentation | Abstract correspondence subject |
| --- | --- |
| A-Sigma | whole pre-load/restored q-scoped relation slice |
| B-Pi | coherent family jointly; component correspondences cannot be independently recombined |

Run a definitional-interpretation check after each delta is completed:

Can every R/L claim of A-Sigma be stated from B-Pi, and every R/L claim of B-Pi from
A-Sigma, using only erasable D_K definitions and no additional existence,
uniqueness, choice, equality, coherence, or restore hypothesis?

If yes, the alternatives are duplicate packaging. Do not retain both; record
relation factorization as OPEN and keep one neutral K0 R/L skeleton. A fixed
role index, tuple construction, projection list, or shared witness does not
justify a fork because it is itself a schema or identity artifact.

If no, the remaining primitive-placement or joint-correspondence difference
must be stated directly in the later card and reviewed against the stop list.
This is not a Canon equivalence or preference claim.

## Structural adversarial cases

Both deltas must account for the following without execution claims.

| Case | Required review |
| --- | --- |
| two q with equal spans, payloads, M1 claims, queue positions, and transport metadata | no effective state sharing from incidental equality |
| one source site dynamically emits twice | distinct semantic residence without source/span identity |
| two principals at one requester locus | relation reference does not collapse authority or correlation |
| owner success with no accepted receipt | no implicit acceptance/use fact |
| accepted/unconsumed saved and restored | required live facts and closure are visible |
| consumed saved and restored | no reset claim is made from static correspondence |
| incomplete closure | candidate identifies missing primitive/derived input rather than hiding it |
| two independent loads | no equality or globally stable anchor assumed |
| B-Pi component splice | joint correspondence must prohibit constructing one restored account from unrelated pre-load components |
| A-Sigma bundle reuse/equality | fiber cannot become an exchange token or restore key |

Each outcome is an obligation, OPEN item, Canon gap, out-of-scope result, or
candidate elimination. It is not dynamic evidence.

## Elimination and ordinary-boundary stop conditions

Eliminate A-Sigma when fiber opacity hides fact-level closure, or when the fiber
becomes an exchange object, equality subject, unique envelope, record,
complete projection set, tagged lifecycle, or persistence key.

Eliminate B-Pi when family membership is not semantic state, coherence uses a
latent record/token/common witness, its index becomes a schema, coherence
encodes lifecycle/transition, or its restore handling permits component splice.

Stop an affected card for ordinary Canon process when it needs a concrete schema
or field layout, key/public/global identity, transition/lifecycle, occurrence
kind/causal generator, failure member/row, restore function, Config/SaveObject
field, serialization, runtime, source form, observation/export, theorem/OBL,
conformance, Gate, Phase, or public claim. The card is not repaired by adding
the reserved surface.

## Material that remains OPEN

The preflight may choose only presentation granularity and abstract
correspondence subject. It must leave OPEN:

- relation arity, carrier types, constructors, equality, and exact family count;
- first-class exchange object or ID;
- concrete pending binding representation;
- M1/provenance, branch, result, receipt, acceptance, and use structures;
- concrete Config/SaveObject/channel placement, serialization, restore function,
  or occurrence equality;
- correspondence totality, functionality, injectivity, surjectivity, no merge,
  no duplicate, no reset, no revalidation, and no stale resurrection;
- validation/fail-closed algorithm and failure-row membership;
- semantic receipt/acceptance transition, Gamma/Delta disposition,
  consumption representation, occurrence accounting, causal mapping,
  observation, proof, and runtime.

## Disposition and non-effects

Proceed with the A-Sigma/B-Pi delta comparison only as an OPEN K0 R/L factorization
preflight. It is not conditional compatibility, a carrier selection, a relation
model, a proof, or an implementation plan. If the primitive-placement delta
cannot be stated without a fixed field inventory, unique bundle identity, latent
common witness, or restore mechanism, collapse the fork to one neutral skeleton
with relation factorization OPEN.

relation schema, identifier, transition, occurrence, causal family, failure
row, authority rule, observation surface, source grammar/elaboration, runtime,
adapter, wire/API, theorem/OBL, scenario, Gate, Phase, sample, implementation,
