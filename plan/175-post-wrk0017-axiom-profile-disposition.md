4. use the result to decide a pre-declared retain/reject branch for that exact

This differs from WRK-0017 only if it measures elaborated proof-term dependency
profiles and drives that pre-declared decision. It must not change the frozen
record's former compile-failure falsifier or claim that generic domains lack
constructive proofs.

## Disposition

**No candidate at the current cut.** The two expected profiles are already
recorded in Report 2377. The exact local predicate has no existing source-level
consumer of a retained theorem, `Decidable` value, failed-subset witness, or
proof-hygiene artifact. Re-running those known diagnostics without a consumer
would be a control repair / known-result replay, not a decision-relevant L3
experiment.

No fresh WRK, Lean source edit, outcome command, generated artifact, helper,
schema, CI, Make target, or runtime work is authorized by this disposition.

## Reopen conditions

Reopen only when all conditions hold:

1. an exact existing consumer names the binary decision that a retained local
   theorem would settle;
2. the question is pre-registered as a fresh forward L3 successor, with
   `Supersession: WRK-0017`, rather than a repair of WRK-0017;
3. the record pins the source digest, Lean version, theorem shape, allowed
   local proof mechanism, profile output expectations, same-target classical
   control, generic classical control, and retain/reject branch; and
4. all non-claims exclude generic constructivity, `Decidable` value/API,
   checker/OBL/Line-1 movement, Canon changes, and public completion.

The successor must freeze if the local profile is nonempty, either classical
control evades its expected profile, an excluded mechanism is required, or the
result no longer drives the declared consumer decision.

## Forward research order
