## Meaning and direct consumer

A pure expression selects a first-class module interface and computes an argument.
The current module boundary checks that actual request, local contract evidence,
code/contract identity and an independent resource grant before allocating a
region. A finite computation then splits, transfers and releases actual resources.
Its lexical values, live resource rights and pending instructions survive
suspension. The same captured computation resumes once within one state history.
World/Avatar and communication operations are not added as Core primitives.

| Component | Independent meaning / checked consequence |
|---|---|
| `Source`, `Typed`, `Selects` | Interface and integer argument expressions; `check_exact`, `select_sound`, `select_complete` |
| `request`, `invocation`, `allocateOnce` | Evaluated interface/argument bind to current module use, proof, separate grant and shared semantic request history; `request_fields`, `invocation_exact`, `allocateOnce_preserves` |
| `ResourceContext.Delta` | Permission map keyed by actual identity, realized in live state; `Owned` and `Allowed` versus `execute_exact`; all four resource actions preserve realization |
| `Sequence` | Pure let, allocation, release, move and split with actual state/events; `run_good`, `run_rights`, `step_failure`, `run_append` |
| `Sequence.Semantics` | Unbounded declarative `Transition`/`Runs`; evaluator budget is absent from semantic outcomes; `completed_run_sound`, `runs_eventually` |
| `Sequence.Typing` | Separate pure type environment and resource-reference shape; independent command/program judgments versus inference; preservation and `checked_program_eventually` |
| `Continuation` | Actual lexical frame, pending body and position; capture removes runnable phase, resume consumes token before tick; `schedule_good`, `schedule_typed`, `no_revival`, `drive_sequence` |
| `Sequence.Rows` | Actual successful effects are a declared prefix; typed semantic failures lie in their row; residual obligations are actual pending instructions |
| Mixed retirement | `run_retired`, `run_history`, `committed_call_rejected` retain consumed resource and request identities through actual mixed computation |

Gamma is the pure value/type environment. Delta is an exact dynamic permission
map, not a second permission for each metadata alias. Place/lifetime/version and
authority inputs remain in the existing current execution context and boundary
checks; they are neither erased nor generated by the type checker. Resource
metadata names have a static shape, while stale alias use can still fail dynamically.
A stronger static affine judgment remains the smallest alternative; it
would retain the dynamic currentness and authorization guards.

`checked_program_eventually` quantifies over checked finite programs with a valid
initial environment/state and fixed supplied context function. It gives an actual
semantic outcome and a sufficient evaluation budget. It does not imply successful
authorization, acceptance of every true certificate, a uniform resource bound,
or eventual availability of a real provider. The admission relation explicitly
retains acceptance of the submitted certificate as a relative premise.

## Exact control/context correspondence

`ControlIndexed.Step` indexes each successful or denying semantic transition by
the context in that exact tick control. `Scheduled` composes the ordered controls;
`act_sound`/`schedule_sound` connect the actual scheduler. Structural capture,
resume, inactive and retry rules state their own configuration changes.
`scheduled_forget` derives the previous existential-context prefix and status
predicates. `checked_control_schedule` and `captured_control_schedule` preserve
the stronger relationship for the same typed/captured consumer.

`denied_tick_position` proves that a pending allocation under an always-denying
grant cannot advance in this independent relation. The concrete
`context_substitution_rejected` theorem excludes an allowing endpoint for the
corresponding denying control, although the older context-forgetting predicate
could describe that endpoint. Context-forcing mutations fail the general
`act_sound`, in addition to concrete grant controls.

This relation abstracts fuel adequacy for completed semantic outcomes; it is a
one-way simulation, not a fuel-exact equivalence. Only its budget-pause rule uses
the actual bounded step's budget predicate, under the same supplied context.
A zero-fuel pure literal can therefore advance abstractly although the concrete
step pauses. The final configuration does not retain a context receipt.
Budget is not an authorization denial. Existing sufficient-fuel semantic
completeness remains separate from arbitrary scheduler liveness.

## Nontrivial controls and falsifiers

The same program with inputs3/4 creates a pure closure computing4/5, calls one
symbolic square-plus-one module to allocate length17/26, and executes real split,
move and release. No branch recognizes an example name. Later failure retains
already allocated rights/events. Stale aliases and repeated semantic requests
are denied. An old proof rejects a changed argument. Captured frames retain
values and rights; supplied revocation, changed code or denied grant prevents
an effect. Budget exhaustion after allocation retries only the actual residual.
Additional controls select two actual interfaces by a pure expression, use both
contract profiles, release one of two distinct rights, retry a budget-limited
residual through capture/resume, and change the later grant. Foreign captures with
the same integer3 retain distinct public/secret declarations; secret-to-public
completion and secret overflow are rejected before starting the consumer.
These fixed controls use `decide`/reduction and are not general proofs.

Eighteen mutations change actual code: selected argument/interface, resource
consumption, failure rights, prefix events, resume consumption, captured values,
failure row, resource-name checking, request history, independent grant, shared-update rights loss, failed residual loss,
capture completion admission, capture metadata, captured-value fabrication, and
substitution of an always-allowing or always-denying context at the scheduler boundary.
The checker requires a failure at a designated general theorem, not merely any
Lean syntax error. The unchanged baseline must pass first. All results are
written outside the repository and no prior mutation result is reused.

`MirroreaProofFirstResourceComputationScopeControls.lean` also gives a decisive
limit: allocation under a one-identifier bound succeeds, then the mathematical
split creates identities beyond that bound. It prevents misreading per-allocation
capacity checking as whole-program capacity. Reusing an old supplied context and
replaying an old whole configuration are outside freshness/single-history claims.

## Assumptions, TCB and implementation obligations

The trusted computing base includes Lean4.29.1's kernel/toolchain. Printed logical
axioms are `propext`, `Classical.choice`, `Quot.sound`; no Mir-specific axiom,
`sorry` or `admit` establishes a claim. Classical existence/completeness is not
an efficient budget-selection algorithm.

- Resource arithmetic and generic split/move/release use mathematical Nat/Int.
  They do not enforce the allocation context's finite identifier bound. Every
  machine mutator needs a coherent bound/refinement before production reliance.
- The scheduler profile has one active OR suspended finite frame. It has no
  general effect handlers, multiple independent frames, general effect recursion,
  transferred/serialized continuation capability, or same-instance recovery.
- Tokens are private controls within one authoritative state history. Copying
  an old whole configuration is rollback, not a permitted scheduler action.
  Physical serialization and anti-rollback must implement that assumption.
- Current World/registry/catalog/policy inputs are supplied separately at each
  step. Their freshness/authenticity is not proved by supplying them. Existing
  resource principal policy is not all layers of module/identity authorization.
- Strong shared-request nonduplication applies to `allocateOnce`/`Sequence`.
  History-free allocation helpers are comparison primitives. `boundaryDenied`
  covers several semantic failures; it does not identify a specific policy layer.
- Split cuts and move receivers are literal Nat in this finite instruction profile.
  Reusable computed-cut resource functions and a final Core restriction are not claimed.
- Event lists contain actual successful operations. They are not public telemetry
  contracts, complete request/serve/result provenance or two-run confidentiality.
- Named pure expressions have earlier elaboration evidence; the new effect
  sequence is typed Core. No general ordinary-source/Rust/runtime/transport
  refinement, source-driven installation, dynamic hot-plug or alpha E2E follows.

The direct consumer remains W2 expressive/type/boundary research. Production
integration, W3 and alpha work do not proceed in this W2-only run.
