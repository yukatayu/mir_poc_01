# W4 publication model — LAB candidate

This is one dependency of active W4, not W4 completion, a production protocol,
Canon acceptance or Plan250/I3-4 resume. Report2614 accumulates its evidence.
The direct consumer is configuration/authority currentness at source-generated
owner requests, completion and control entries. Authority generation and the
publication protocol revision are different coordinates.

## Definitions and checked claims

`Publication` defines an independent `Allowed` relation, Boolean checker and
executor over a fixed finite cohort. A publisher emits a freeze round;
participants raise monotone fences before acknowledging; publication requires
all acknowledgements; authentic retained certificates can reopen only a current
endpoint. The general finite-history invariant is
`installed ≤ published ≤ fence` and `ack ≤ fence`, with retained ACK origins.
Checking `installed = fence` therefore implies currentness without testing the
conclusion at publication. Duplicate and reordered messages do not lower floors.

`PublicationPayload` relates complete cached values to immutable published
images and the actual pure evaluator result. `PublicationSession` instantiates
this with all six existing W3 entries and proves a state-level refinement.
That theorem intentionally does not preserve an entry's return interface.
`PublicationOutcome` supplies the additional labelled relation, preserving
created IDs, actual cancellation outcomes and generated reply ordinals. Its
publication theorem associates the published result with the exact evaluated
command. A denied cancellation can return an unchanged Session with a rejection;
neither evaluator `some` nor publication means successful cancellation.

Those two evaluators retain the local reference model's unrestricted waiting
`tick`; they must not be exposed as physical result-producing entries.
`ReceivedResult` accepts an explicit saved pending entry and integer, checks the
existing protected finish, and proves exact correspondence to reference success.
It does not establish owner execution, authenticity or every failure outcome.
`PublicationExecution` uses one closed command relation for both source driving
and publication. Source `tick` requires ready status; waiting-result writes require
the explicit received-result entry, including when the result is published.
Its Snapshot preserves the actual command, result and generated ordinal. From an
empty authentic history root, ordinals stay unique; this does not grant a finite
allocator permission to reset after compaction. Rooted Session invariants survive.
Every independently admitted Entry has a finite normal publication under the
same nonempty/reachable/settled/free conditions. The immutable refused-input
wrapper preserves the whole Session and reports only a coarse refusal. A mutable
receiver and truthful detailed transport reason remain implementation obligations.

`PublicationUse` represents a local validation-to-use interval. Freeze/install
wait for the interval to end. The absence of all active intervals at publication
is derived from the invariant and ACK guards, rather than assumed as the desired
conclusion. A held value remains equal to the current published value.

`PublicationProgress.normal_payload_succeeds` proves a useful finite schedule
for every nonempty finite cohort, arbitrary reachable settled state with no
held intervals, and evaluable command. Stage, all freezes, all ACKs, publication
and all installations succeed; each endpoint has the exact resulting value and
can enter. This uses a proved emitted-round upper bound, payload availability
and historical-image immutability. It is not fairness, universal completion,
owner/network availability, or progress of a no-op source command.

## Comparisons and evidence classes

Concrete controls exercise two rounds, old/duplicate/reordered packets, missing
ACKs, stale installations, live intervals and actual parser-generated W3 source.
Weakening comparators expose stale-enabled states when accepting unissued ACKs,
omitting a participant, omitting fence advancement or publishing the wrong
revision. Omitting only the install floor permits stale installation while the
separate use gate remains closed; it is not a stale-use counterexample.
Saved validation and forged payload examples identify external representation
obligations, not reachable failures of the closed model.

Outcome controls distinguish two created IDs, absent pending work, denied
cancellation and subsequent authorized cancellation. The source control's
head-change example retains an old pending result and rejects its stale result;
it does not establish automatic resolution after permanent authority loss.
The closed execution controls exhibit the older publication waiting-tick bypass,
reject it through the new entry, and run all17source statements with explicit
model result inputs, retaining17writes and21command replies. Wrong id/value,
valid-after-invalid, duplicate result and pending authority change are separate
controls. Their input values are locally computed and are not owner-process evidence.
An additional unsafe projection comparator prepares a full Session at count2,
executes an ordinary count3 write, then loses that write by installing the old
prepared Session. Such overlapping updates are outside admitted model traces.
Fixed controls and eight designated proof-script mutations are not general proofs.

## TCB, conditions and unclosed obligations

Lean4.29.1 with `--trust=0` checks general propositions; the all-owned audit
allows only `propext`, `Quot.sound` and inherited W3 `Classical.choice`.
The kernel/toolchain and actual parser/adapter/source receipt chain remain
trusted implementation boundaries. There are no Mir-specific proof axioms.

The model assumes authentic retained message content, a fresh admitted namespace,
a complete fixed participant set, pure evaluation and serialized transitions.
These are explicit modelling conditions, not physical mechanisms already proved.
Unbounded naturals/lists/functions are not a finite codec, numeric profile,
retention or resource-exhaustion policy. There is no timeout reopening rule.

Full-Session equality is a reference relation. It does not authorize copying
owner-private state to participants or executing owner effects at a publisher.
The actual runtime must bind source/Core/edge provenance, realm/cohort and
incarnations, payload identity, exact ACK origins and all relevant use gates.
Domain pending work is distinct from an active local critical section.
A physical operation cannot hold a guard while waiting for its own publication;
preparation, owner execution, result arrival, acceptance, mutation and guard
release need explicit linearization. Mathematical `finish i` is not a remote
release token or domain completion; a private nonduplicable guard must discharge
ownership and delayed-release obligations. Pure administrative `use` cannot be
exported as reusable permission. Evaluator execution in both `check` and `apply`
must never be translated into duplicate effectful execution.

Head admission and effective time, Q18, continuing entitlement H/H2 and
cancellation C/C2 remain separate conditional policy choices. W5 persistence,
W6 secret observation and the final alpha profile remain later obligations.
The first three Oracle reviews cover the numeric/payload/interval cut and the
subsequent outcome/progress/received-result additions. The third exposed the
waiting-tick composition bypass, verified locally. The new closed execution
response and projection counterexample were reviewed by the fourth Oracle. The actual source/Core/owner join remains open. Oracle is advisory,
not an executed proof, owner decision or cryptographic reviewer signature.
